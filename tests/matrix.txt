# Configuration matrix of tests/regress.sh (see doc/rewrite/ROADMAP.md 0.1).
#
# name | solver options | proofs yes/no | counters that must be nonzero | kind [| limit]
#
# proofs: whether the Lean checker verifies the proofs of this configuration.
# counters: names of "c stat NAME VALUE" lines; each must be nonzero on at
#   least 10% of the search-tier instances that finished.
# kind: "normal" or "stress". Stress rows force rare paths (reduction, garbage
#   collection, restarts) and fail the run when more than their limit of the
#   search-tier instances time out; for normal rows that only warns.
# limit: optional, stress rows only: the percentage of search-tier timeouts
#   that fails the run (default 2). A limit above 2 needs a measurement against
#   the baseline: see doc/rewrite/STATUS.md, "Coordinator decisions after M1
#   round 1", D1.
#

# M2-T6: the three rows above restart after every conflict and want level 0
# every time (the dependency resets need it, and root simplification only
# runs there), which trail reuse would mostly prevent, so they run with
# --no-reusetrail.  The rows below restart as often as the glue averages
# allow (fast average of window 1 = last glue, slow of window 2, no margin,
# one conflict apart, dependency reset every conflict) with reuse on, so
# that partial backtracks meet reductions, collections, resets and
# root simplification.  ema-stress-dl has the limit 4: restarting after every
# conflict with -dl is slow by nature (restart-dl has 8); measured on seeds
# 1:300 (STATUS.md H7), the same options with --no-reusetrail time out on 6 of
# 150 search instances, with reuse on 4 of 150.
